# Code of Conduct

Gosslens is built in public by people with different backgrounds, experience,
and working styles. Keep the project technical, respectful, and useful.

## Expected

Be direct without being hostile. Critique code, architecture, tests, and ideas;
do not attack the person behind them. Assume good faith until the work gives a
reason to discuss a concrete problem.

Give review feedback that can be acted on. Explain the defect, the violated
contract, or the missing proof. Accept the same standard when your own work is
reviewed.

Respect boundaries. Do not publish another contributor's private information,
private conversations, credentials, security material, or local-only project
material.

Keep disagreements on the work. Technical disagreement is normal. Harassment,
threats, discrimination, sexual harassment, stalking, intimidation, and
sustained personal abuse are not.

## Scope

This code applies in repository issues, pull requests, reviews, discussions,
project chat, project events, and other spaces where someone is representing
Gosslens.

## Enforcement

Project maintainers may edit or remove comments, reject changes, lock threads,
or temporarily or permanently restrict participation when behavior violates
this code.

Serious conduct concerns should be reported privately to the project
maintainers rather than litigated in a public issue. Reports should include the
relevant context and links where available. Maintainers will limit disclosure
to what is needed to review and resolve the report.

Retaliation against someone who raises a good-faith conduct concern is itself a
violation.

## One standard

Technical standards can be strict without making the project unpleasant. Hold
the code to a high bar and treat contributors like people.
